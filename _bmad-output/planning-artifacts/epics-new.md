## Requirements Inventory

### Functional Requirements (11개)

**FR-001: 캔버스 진입**
사용자가 루트 경로(`/`)로 접근 시 린스타트업 캔버스가 1초 이내에 로딩되어야 한다.

**FR-002: 노드 생성**
사용자가 빈 캔버스 더블클릭 시 7단계 노드 타입 선택 모달이 표시되어야 하며, 타입 선택 후 500ms 이내에 새 노드가 생성되어야 한다.

**FR-003: 노드 이동**
사용자가 노드를 드래그하여 캔버스 상에서 자유롭게 이동할 수 있어야 하며, 드래그 응답 지연시간이 100ms 이내여야 하고 드래그 종료 시 위치가 저장되어야 한다.

**FR-004: 노드 연결**
사용자가 Shift+드래그로 한 노드에서 다른 노드로 연결선을 생성할 수 있어야 하며, 연결선이 100ms 이내에 렌더링되어야 하고 연결선에 화살표로 방향을 표시할 수 있어야 한다.

**FR-005: 노드 상세 보기**
사용자가 노드 클릭 시 우측 사이드바가 200ms 이내에 로딩되어야 하며 해당 노드의 상세 내용을 확인하고, AI와 대화하여 내용을 수정할 수 있어야 한다. AI 제안 승인율은 70% 이상 목표이며, 사용자 수정 반영은 1초 이내에 처리되어야 한다.

**FR-006: 진행 상태 시각화**
시스템이 각 노드의 완료 상태를 색상(회색/노란색/초록색)으로 시각화하고, 헤더에 "완료 X/7"과 진행률 바를 표시해야 한다.

**FR-007: 온보딩 튜토리얼 (Hybrid Approach)**
첫 방문자가 AI 인사와 Proactive 제안을 통해 10분 내 첫 번째 노드를 생성하고 완성할 수 있어야 하며, 간소화된 캔버스 경험을 제공해야 한다.

**FR-008: 정부지원사업 내보내기**
사용자가 3개 이상 노드 완료 시 부분 초안 내보내기가 가능해야 하며, 7개 노드 완료 후 AI 기반 문서 변환을 시작해야 한다. AI 변환 성공률은 85% 이상이어야 하고 생성 시간은 10초 이내여야 하며, 생성된 문서를 PDF, DOCX로 다운로드할 수 있어야 한다.

**FR-009: 부분 진행 상태 내보내기**
사용자가 3개 이상 노드 완료 시 부분 내보내기 버튼이 표시되어야 하며, 클릭 시 5초 이내에 완성된 노드 내용을 기반으로 초안을 생성해야 한다. 시스템은 미완성 노드를 "미완성: [노드명]" 형식으로 명시하고 완성 권장사항을 3개 이하로 표시해야 한다.

**FR-010: AI API 에러 처리**
외부 AI 서비스 호출 실패 시 사용자에게 명확한 에러 메시지를 표시하고, 재시도 버튼을 제공해야 한다. 3회 연속 실패 시 지원 티팅 안내를 표시해야 한다.

**FR-011: 네트워크 오류 안내**
네트워크 연결 불량 시 "오프라인 모드로 작동 중" 알림을 표시하고, LocalStorage에만 저장한다. 온라인 복구 시 자동으로 서버와 동기화한다.

### Non-Functional Requirements (15개)

**NFR-001: 페이지 로드 성능**
캔버스 페이지를 2초 이내에 로드 (Chrome DevTools, 3G 네트워크 기준)

**NFR-002: 노드 생성 성능**
새 노드 생성을 500ms 이내에 완료 (Performance API 측정)

**NFR-003: AI 응답 속도**
- 짧은 질문(100자 이내): 2초 이내 응답 시작, 5초 이내 완료
- 긴 질문(100자 이상): 3초 이내 응답 시작, 10초 이내 완료
- 응답 생성 중 "AI가 내용을 생성하고 있습니다..." 진행률 표시

**NFR-004: 확장성 - 100 WAU**
단일 데이터베이스 인스턴스 지원 (수직 확장)
- 응답 시간: P95 < 500ms 유지
- 리소스 사용량: CPU < 70%, 메모리 < 80%

**NFR-005: 확장성 - 1,000 WAU**
데이터베이스 인덱싱 최적화, 캐싱 전략 적용
- 응답 시간: P95 < 1초 유지
- 캐시 적중률: 80% 이상

**NFR-006: 확장성 - 10,000 WAU**
CDN 배포, 읽기 전용 인스턴스 분리
- 응답 시간: P95 < 2초 유지
- 가용성: 99.9% SLA

**NFR-007: AI 비용 최적화**
- 프롬프트 템플릿 로딩 시간: 100ms 이내
- Claude API 200K 토큰 윈도우 사용
- 응답 캐싱: 단기 캐싱 (1시간) + 장기 저장 (벡터 DB)
- 비용 모니터링: 월간 AI API 사용량 추적 및 예산 알림

**NFR-008: 접근성 - 키보드 및 단축키**
키보드 단축키 지원 (Ctrl+Z: 실행 취소, Del: 삭제)

**NFR-009: 접근성 - 모바일 반응형**
태블릿, 모바일 반응형 지원 (320px-1920px 브레이크포인트)
- 터치 drag & drop (150ms 내 응답), 핀치 줌, 모바일 최적화된 레이아웃

**NFR-010: 접근성 - WCAG 준수**
색맹/고대비 모드 지원 (WCAG AA 대비율 4.5:1 준수)
WCAG 2.1 AA 준수: 대비율 4.5:1, 키보드 내비게이션, 초점 표시

**NFR-011: 호환성 - 브라우저**
Chrome 90+, Safari 14+, Edge 90+, Firefox 88+ 지원
iOS Safari, Chrome Mobile 지원
권장 화면 크기: 1280px 이상
Progressive Enhancement 전략

**NFR-012: 데이터 - 상태 관리 및 저장**
상태 관리: 클라이언트 상태 관리 + 서버 상태 동기화 기능
데이터 저장: 노드 위치, 연결선, 내용을 10초마다 자동 저장
충돌 처리: 즉시 UI 반영 + 충돌 시 "변경 사항이 있습니다" 알림

**NFR-013: 데이터 - 오프라인 지원**
오프라인 지원: LocalStorage 백업 + 서버 동기화 (온라인 시 자동 저장, 오프인 시 LocalStorage만 사용)
온라인 복구 시 5초 이내 자동 동기화 (최근 변경사항 우선)

**NFR-014: 데이터 - 버전 관리**
복구 기능: 버전 이력 (최근 10개 버전 저장, 1분마다 스냅샷)

**NFR-015: AI 맥락 인식 (Co-Founder Positioning)
AI가 이전 노드 내용 기반 연속적 질문과 개인화된 피드백 제공
린스타트업 방법론 기반 질문 (단순화된 질문, 기술 용어 제거)

### Epic 1 Stories

#### Story 1.1: AI 인사와 사용자 상태 파악

**사용자:** 첫 방문자
**원하는 기능:** AI Co-Founder의 인사와 나의 현재 상태를 선택할 수 있는 3가지 옵션
**가치:** 진입 장벽을 최소화하고 나에게 맞는 온보딩 경험을 제공받을 수 있다

**Acceptance Criteria:**

**Given** 사용자가 루트 경로(`/`)로 접근한다
**When** 페이지가 로딩된다
**Then** 1초 이내에 AI 인사 메시지가 중앙 상단에 표시된다
**And** AI 인사는 반갑고 친근한 톤으로 "안녕하세요! AI Co-Founder입니다" 형식이다
**And** 인사 아래에 3가지 옵션 카드가 수평 정렬로 표시된다

**Given** 3가지 옵션 카드가 표시된다
**When** 각 옵션을 확인한다
**Then** 옵션 1: "이미 스타트업 아이디어가 있어요" - 아이디어 입력으로 바로 이동
**And** 옵션 2: "아직 아이디어가 없어요" - 문제 발굴 가이드로 이동
**And** 옵션 3: "팀과 함께하고 있어요" - 팀 온보딩 가이드로 이동
**And** 각 옵션 카드는 클릭 가능하고 hover 시 강조 표시된다

**Given** 사용자가 옵션을 선택한다
**When** 옵션 카드를 클릭한다
**Then** 선택한 옵션에 맞는 온보딩 모드로 자동 전환된다
**And** 선택한 옵션이 localStorage에 저장된다 (다음 방문 시 자동 적용)

**Given** 사용자가 이미 경험이 있다
**When** 우측 상단 "건너뛰기" 버튼을 클릭한다
**Then** 온보딩을 건너뛰고 메인 캔버스로 바로 이동한다
**And** "건너뛰기" 선택이 localStorage에 저장된다 (다음 방문 시 자동 건너뛰기)

**Given** 오프라인 상태로 접속한다
**When** 네트워크 연결을 확인한다
**Then** "오프라인 모드로 작동 중입니다" 알림이 표시된다
**And** 모든 온보딩 기능이 정상 작동한다 (LocalStorage에만 저장)
**And** 네트워크 복구 시 자동으로 서버와 동기화된다

**Given** 사용자가 이전에 방문한 적이 있다
**When** localStorage에 옵션 선택이 저장되어 있다
**Then** 이전 선택을 기반으로 해당 옵션으로 자동 진행한다
**And** "이전에 선택한 옵션: [옵션명]" 메시지가 2초간 표시된다

**Given** 모바일 기기로 접속한다
**When** 화면이 로딩된다
**Then** 옵션 카드가 세로 정렬로 표시된다
**And** 각 카드는 최소 44px 높이로 터치 가능하다 (WCAG 2.1 AAA)

#### Story 1.2: Adaptive 온보딩 모드 캔버스

**사용자:** 첫 방문자 (옵션 선택 후)
**원하는 기능:** 간소화된 캔버스에서 AI 가이드와 함께 첫 노드 생성
**가치:** 복잡한 캔버스 기능 없이 핵심 기능만으로 빠르게 시작할 수 있다

**Acceptance Criteria:**

**Given** 사용자가 옵션 1(아이디어 있음)을 선택했다
**When** 간소화된 캔버스가 로딩된다
**Then** "초보자 모드"로 캔버스가 표시된다
**And** 상단에 "AI 가이드가 활성화되었습니다" 토글이 켜진 상태로 표시된다
**And** 캔버스 중앙에 "더블클릭하여 첫 번째 노드를 생성하세요" 도움말이 표시된다

**Given** 사용자가 옵션 2(아이디어 없음)를 선택했다
**When** 캔버스가 로딩된다
**Then** "문제 발굴 모드"로 캔버스가 표시된다
**And** AI 가이드가 자동으로 3가지 질문을 제시한다
**And** 질문 1: "어떤 분야에서 문제를 발견하고 싶으신가요?"
**And** 질문 2: "본인이나 주변에서 겪은 불편한 점이 있나요?"
**And** 질문 3: "해결하고 싶은 특정 문제가 있나요?"

**Given** 사용자가 옵션 3(팀과 함께)를 선택했다
**When** 캔버스가 로딩된다

**Then** 500ms long press 후 노드 타입 선택 모달이 표시된다
**And** haptic feedback이 제공된다 (지원 기기 한)
**And** 모달이 하단에서 슬라이드 업으로 표시된다

**And** 자동 레이아웃 조정이 적용된다

**Given** 오프라인 상태에서 노드를 생성한다
**When** 생성이 완료된다
**Then** LocalStorage에 노드가 저장된다
**And** "오프라인 모드: 노드가 로컬에 저장되었습니다" 토스트가 표시된다

#### Story 2.3: 노드 드래그 앤 드롭 이동

**사용자:** 캔버스 사용자
**원하는 기능:** 노드를 드래그하여 캔버스 상에서 자유롭게 이동
**가치:** 원하는 위치에 노드를 배치하여 캔버스를 체계적으로 구성할 수 있다

**Acceptance Criteria:**

**Given** 사용자가 노드를 클릭한다
**When** 마우스 버튼을 누른 상태로 이동한다
**Then** 100ms 이내에 드래그가 시작된다
**And** 노드가 반투명(70% 투명도)으로 표시된다
**And** 노드 상단에 "이동 중..." 표시가 나타난다
**And** 드래그 중인 노드가 z-index 100으로 다른 노드 위에 표시된다

**Given** 드래그가 진행 중이다
**When** 노드를 이동한다
**Then** 노드 위치가 실시간으로 업데이트된다

**And** 드래그 응답 지연시간이 100ms 이내이다
**And** 캔버스 외부로 노드를 이동할 수 없다 (경계 제한)

**Given** 드래그를 종료한다 (마우스 버튼 릴리스)
**When** 드래그가 완료된다
**Then** 노드가 최종 위치에 고정된다

**Given** 여러 노드를 동시에 선택한다
**When** Shift 키를 누르고 여러 노드를 클릭한다
**Then** 선택된 모든 노드가 하이라이트된다
**And** 하나의 노드를 드래그하면 선택된 모든 노드가 함께 이동한다
**And** 노드 간 상대 위치가 유지된다

**Given** 캔버스 라이브러리로 @dnd-kit/core를 사용한다
**When** 드래그 앤 드롭을 구현한다
**Then** DndContext가 캔버스 컴포넌트를 래핑한다
**And** useDraggable 훅이 각 노드에 적용된다
**And** DraggableOverlay가 드래그 중인 노드를 렌더링한다
**And** onDragEnd 이벤트 핸들러로 위치가 저장된다

**Given** Konva.js 캔버스를 사용한다

#### Story 2.4: 노드 연결 (Shift+드래그)

**사용자:** 캔버스 사용자
**원하는 기능:** Shift+드래그로 노드 간 연결선 생성
**가치:** 노드 간 관계를 시각화하여 흐름을 명확히 표현할 수 있다

**Acceptance Criteria:**

**Given** 사용자가 Shift 키를 누르고 노드를 드래그한다
**When** 연결 모드가 활성화된다
**Then** 노드 4면에 앵커 포인트(6px 원형)가 표시된다 (top, bottom, left, right)
**And** 앵커 포인트는 해당 노드 색상으로 표시된다
**And** 가장 가까운 앵커 포인트가 자동으로 하이라이트된다

**Given** 연결 모드에서 앵커 포인트를 클릭한다
**When** 다른 노드의 앵커 포인트로 드래그한다
**Then** 드래그 중 직선 연결선이 표시된다
**And** 연결선은 100ms 이내에 렌더링된다
**And** 연결선 색상은 회색 (#9ca3af)이다
**And** 연결선 너비는 2px이다

**Given** 대상 노드의 앵커 포인트에 드롭한다
**When** 연결이 완료된다
**Then** 직선이 Bezier 곡선으로 변환된다
**And** 곡선은 부드러운 S자 형태이다
**And** 곡선 끝에 화살표가 표시된다 (6px SVG marker)
**And** 화살표 방향은 소스 노드 → 타겟 노드이다
**And** 연결 데이터가 저장된다 (sourceNodeId, targetNodeId, sourceAnchor, targetAnchor)

**Given** 연결선이 표시된다
**When** 연결선을 확인한다
**Then** 연결선은 SVG path로 렌더링된다
**And** path는 `M x1 y1 C cx1 cy1 cx2 cy2 x2 y2` 형식이다
**And** 곡률은 노드 간 거리에 따라 자동 조정된다
**And** 연결선은 z-index 50으로 노드 아래에 표시된다

**Given** 연결선을 더블클릭한다
**When** 연결선을 삭제한다
**Then** "연결을 삭제하시겠습니까?" 확인 모달이 표시된다
**And** 확인 후 연결선이 제거된다
**And** API 호출로 서버에서도 삭제된다

**Given** 연결선을 선택한 상태에서 DEL 키를 누른다
**When** 키보드로 삭제한다
**Then** 연결선이 삭제된다
**And** 확인 모달 없이 즉시 삭제된다
**And** Ctrl+Z로 실행 취소가 가능하다

**Given** 이미 연결된 노드 간에 다시 연결을 시도한다
**When** 중복 연결을 생성하려 한다
**Then** "이미 연결된 노드입니다" 토스트가 표시된다
**And** 중복 연결이 생성되지 않는다

**Given** 같은 노드 내에서 연결을 시도한다 (self-loop)
**When** 자기 자신에게 연결하려 한다
**Then** "자기 자신에게는 연결할 수 없습니다" 토스트가 표시된다
**And** 연결이 생성되지 않는다

**Given** 캔버스 데이터 구조를 설계한다
**When** 연결 데이터를 저장한다
**Then** connections 배열이 존재한다
**And** 각 연결은 {id, sourceNodeId, targetNodeId, sourceAnchor, targetAnchor} 형식이다
**And** 연결 ID는 UUID v4로 생성된다
**And** 노드 삭제 시 관련 연결도 함께 삭제된다 (cascade delete)

**Given** conversationHistory가 로딩된다

**And** conversationHistory가 system message로 전달된다
**And** 현재 노드의 내용이 user message로 전달된다
**And** temperature는 0.7로 설정된다 (creativity balance)
**And** max_tokens는 500으로 설정된다 (간결한 응답)

**And** 피드백 제출 시 "피드백을 저장했습니다. 개선에 반영하겠습니다" 토스트가 표시된다

**And** 3회 연속 실패 시 "지원 팀에 문의해주세요" 메시지가 표시된다
**And** 지원 티켓 링크가 제공된다

**And** 거부 피드백이 서버에 저장되어 AI 모델 개선에 사용된다

**When** 사용자가 제안에 대해 액션을 취한다
**Then** 승인/편집/거부 횟수가 analytics로 추적된다
**And** 목표 승인률은 70% 이상이다
**And** 승인률이 70% 미만일 경우 AI 프롬프트가 자동 튜닝된다

**Then** "오프라인 모드: AI 제안을 사용할 수 없습니다" 토스트가 표시된다

### Epic 5 Stories

#### Story 5.1: 자동 저장 (10초마다)

**사용자:** 캔버스 사용자
**원하는 기능:** 10초마다 자동으로 작업 내용 저장
**가치:** 데이터 손실을 방지하고 안심하고 작업할 수 있다

**Acceptance Criteria:**

**Given** 사용자가 캔버스에서 작업 중이다
**When** 10초가 경과한다
**Then** 자동 저장이 트리거된다
**And** 모든 노드 데이터(위치, 내용, 상태)가 저장된다
**And** 모든 연결선 데이터가 저장된다
**And** 저장 성공 시 "저장됨" 토스트가 1초간 우측 하단에 표시된다
**And** 저장 timestamp가 기록된다

**Given** 사용자가 노드를 이동/편집한다
**When** 변경이 발생한다
**Then** debounce 2s 후 자동 저장이 트리거된다
**And** 10s periodic 저장이 리셋된다 (중복 저장 방지)
**And** 변경된 노드/연결선만 감지하여 증분 저장이 수행된다

**Given** 자동 저장이 진행 중이다
**When** 저장 API가 호출된다
**Then** 요청 형식은 RESTful API POST /api/canvas/save이다
**And** 요청 바디: `{success: boolean, data: {nodes: [], connections: [], timestamp: string}}`
**And** 요청 timeout은 5초이다
**And** 진행 중 indicator가 표시되지 않는다 (background operation)

**Given** LocalStorage First 전략이 적용된다
**When** 자동 저장이 실행된다
**Then** 먼저 LocalStorage에 저장된다 (즉시 완료)
**And** 그 후 서버 API가 호출된다 (비동기)
**And** LocalStorage 저장 성공 시 UI가 즉시 업데이트된다 (optimistic update)
**And** 서버 저장 성공/실패와 무관하게 LocalStorage 데이터가 유지된다

**Given** 서버 저장이 실패한다
**When** API 에러가 발생한다
**Then** "저장 실패: 로컬에만 저장되었습니다" 토스트가 표시된다
**And** LocalStorage 데이터가 유지된다
**And** 실패 횟수가 카운트된다
**And** 3회 연속 실패 시 "네트워크 연결을 확인해주세요" 알림이 표시된다

**Given** 마지막 저장 시간을 표시한다
**When** 헤더를 확인한다
**Then** "마지막 저장: X분 전" 텍스트가 표시된다 (X = 0, 1, 2, ...)
**And** 1분 미만일 경우 "방금 전"으로 표시된다
**And** 1분 이상일 경우 "X분 전"으로 표시된다
**And** 텍스트 클릭 시 "지금 저장" 버튼이 표시된다 (수동 저장)

**Given** 사용자가 "지금 저장"을 클릭한다
**When** 수동 저장이 실행된다
**Then** 즉시 자동 저장이 트리거된다 (debounce 무시)
**And** "저장 중..." 로딩 indicator가 표시된다
**And** 저장 완료 시 "저장되었습니다" 토스트가 표시된다

**Given** 오프라인 상태에서 작업한다
**When** 자동 저장이 실행된다
**Then** LocalStorage에만 저장된다
**And** "오프라인: 로컬에 저장되었습니다" 토스트가 표시된다
**And** 온라인 복구 시 자동으로 서버와 동기화된다

#### Story 5.2: LocalStorage 백업 및 서버 동기화

**사용자:** 캔버스 사용자
**원하는 기능:** LocalStorage 백업 + 서버 동기화 (오프라인 지원)
**가치:** 오프라인에서도 작업할 수 있고 데이터가 안전하게 보호된다

**Acceptance Criteria:**

**Given** 사용자가 캔버스에 진입한다
**When** 앱이 초기화된다
**Then** LocalStorage에서 캔버스 데이터를 로드한다
**And** 데이터 키는 `bm_builder_canvas_data`이다
**And** 데이터 형식: `{nodes: [], connections: [], timestamp: string, version: number}`
**And** 데이터가 없을 경우 빈 캔버스가 표시된다

**Given** LocalStorage에 데이터가 있다
**When** 서버와 동기화가 필요하다
**Then** 서버에서 최신 데이터를 가져온다 (GET /api/canvas)
**And** LocalStorage timestamp와 서버 timestamp를 비교한다
**And** 서버 데이터가 최신이면 서버 데이터를 사용한다
**And** LocalStorage 데이터가 최신이면 LocalStorage 데이터를 서버에 업로드한다

**Given** 오프라인 상태로 진입한다
**When** 네트워크 연결이 없다
**Then** "오프라인 모드로 작동 중입니다" 알림이 우측 상단에 표시된다
**And** 알림 배경은 주황색(#f97316)이다
**And** 모든 작업이 LocalStorage에만 저장된다
**And** 캔버스 기능이 정상 작동한다

**Given** 오프라인 상태에서 작업 중이다
**When** 온라인 상태가 복구된다
**Then** 5초 이내에 자동으로 서버와 동기화된다
**And** "온라인 복구: 동기화 중입니다" 토스트가 표시된다
**And** 최근 변경사항이 우선 적용된다 (latest timestamp wins)
**And** 동기화 완료 시 "동기화 완료" 토스트가 표시된다

**Given** 충돌이 발생한다 (동시 수정)
**When** LocalStorage와 서버 데이터의 timestamp가 다르다
**Then** "변경 사항이 있습니다" 충돌 해결 모달이 표시된다
**And** 두 버전의 timestamp가 표시된다
**And** 2가지 옵션이 제공된다: "서버 유지" / "로컬 유지"
**And** 사용자 선택에 따라 해당 데이터가 적용된다

**Given** 충돌 해결 모달이 표시된다
**When** "서버 유지"를 선택한다
**Then** 서버 데이터가 적용된다
**And** LocalStorage가 서버 데이터로 덮어쓰인다
**And** "서버 버전을 적용했습니다" 토스트가 표시된다
**And** 선택이 localStorage에 저장된다 (다음 충돌 시 자동 선택)

**Given** LocalStorage 용량을 모니터링한다
**When** 저장 용량을 확인한다
**Then** 현재 사용량 / 전체 용량(5MB)이 계산된다
**And** 사용량이 80% 이상이면 "저장 공간이 부족합니다" 경고가 표시된다
**And** 오래된 버전 데이터가 자동으로 삭제된다 (FIFO: 최근 10개만 유지)

**Given** 데이터 백업이 주기적으로 실행된다
**When** 1시간마다 백업이 생성된다
**Then** 백업 데이터가 LocalStorage에 저장된다
**And** 백업 키는 `bm_builder_canvas_backup_{timestamp}` 형식이다
**And** 최대 10개 백업이 유지된다
**And** 사용자가 "백업 복원" 설정에서 백업을 선택할 수 있다

**Given** 모바일 기기에서 사용한다
**When** LocalStorage를 확인한다
**Then** iOS Safari Private Browsing 모드에서도 작동한다
**And** quota exceeded 에러 발생 시 "시크릿 모드에서는 저장이 제한됩니다" 안내가 표시된다
**And** 메모리 내 저장(sessionStorage)으로 대체된다

#### Story 5.3: 버전 관리 (최근 10개)

**사용자:** 캔버스 사용자
**원하는 기능:** 버전 이력 관리 (최근 10개) 및 실행 취소
**가치:** 실수를 되돌릴 수 있고 이전 버전으로 복구할 수 있다

**Acceptance Criteria:**

**Given** 사용자가 캔버스에서 작업 중이다
**When** 버전 스냅샷이 생성된다
**Then** 1분마다 자동으로 스냅샷이 생성된다
**Or** 사용자가 입력/노드 생성/삭제 시 즉시 스냃샷이 생성된다
**And** 스냅샷 데이터: `{id, timestamp, nodes: [], connections: [], description: string}`
**And** 스냅샷 ID는 UUID v4로 생성된다
**And** 최대 10개 스냅샷이 유지된다 (FIFO: 오래된 것부터 삭제)

**Given** Ctrl+Z (실행 취소)를 누른다
**When** 실행 취소가 실행된다
**Then** 이전 스냅샷으로 복원된다
**And** 최대 10단계까지 실행 취소가 가능하다
**And** "실행 취소됨" 토스트가 1초간 표시된다
**And** 캔버스가 이전 상태로 즉시 업데이트된다

**Given** Ctrl+Y (다시 실행)를 누른다
**When** 다시 실행이 실행된다
**Then** 실행 취소 전 상태로 복원된다
**And** 최대 10단계까지 다시 실행이 가능하다
**And** "다시 실행됨" 토스트가 1초간 표시된다

**Given** 버전 이력을 확인한다
**When** "버전 기록" 메뉴를 연다
**Then** 최근 10개 스냅샷이 리스트로 표시된다
**And** 각 스냅샷에 timestamp와 description이 표시된다
**And** description은 자동 생성된다 (예: "노드 '문제 발굴' 생성됨", "노드 이동됨")
**And** 각 스냃샷에 "복원" 버튼이 제공된다

**Given** 특정 스냅샷을 선택한다
**When** "복원"을 클릭한다
**Then** "이 버전으로 복원하시겠습니까? 현재 변경사항은 손실됩니다" 확인 모달이 표시된다
**And** 확인 후 해당 스냅샷으로 캔버스가 복원된다
**And** "버전 복원됨: {timestamp}" 토스트가 표시된다
**And** 복원된 버전이 서버에도 저장된다

**Given** 버전 간 diff를 비교한다
**When** 두 스냅샷을 선택한다
**Then** "변경 사항 보기" 모달이 표시된다
**And** 추가된 노드가 초록색으로 강조된다
**And** 삭제된 노드가 빨간색 취소선으로 표시된다
**And** 수정된 노드가 파란색으로 표시된다
**And** 노드 내용 변경 사항이 side-by-side로 표시된다

**Given** 스냅샷이 자동으로 생성된다
**When** description이 자동 생성된다
**Then** 노드 생성: "노드 '{title}' 생성됨"
**And** 노드 삭제: "노드 '{title}' 삭제됨"
**And** 노드 이동: "노드 이동됨"
**And** 내용 수정: "노드 '{title}' 수정됨" (100자 이상 변경 시)
**And** 연결 생성: "연결 생성됨"
**And** 연결 삭제: "연결 삭제됨"

**Given** 사용자가 수동으로 버전을 생성한다
**When** "버전 저장" 버튼을 클릭한다
**Then** "버전 이름을 입력하세요" 모달이 표시된다
**And** 사용자가 custom description을 입력할 수 있다
**And** 입력 후 스냅샷이 즉시 생성된다
**And** "버전 '{name}' 저장됨" 토스트가 표시된다

**Given** 스냅샷 데이터가 LocalStorage에 저장된다
**When** 저장소를 확인한다
**Then** 데이터 키는 `bm_builder_canvas_snapshots`이다
**And** 데이터 형식: `{snapshots: [{id, timestamp, data, description}], currentIndex: number}`
**And** currentIndex는 현재 작업 중인 스냅샷 인덱스이다
**And** 용량 제한: 최대 10개 스냅샷 (FIFO 자동 삭제)

**Given** 키보드 단축키를 사용한다
**When** Ctrl+Z/Ctrl+Y를 누른다
**Then** Mac에서도 Cmd+Z/Cmd+Shift+Z가 지원된다
**And** 단축키가 전역에서 작동한다 (사이드바 포함)
**And** 화면 reader가 "실행 취소됨" / "다시 실행됨"을 읽어준다

**Given** IndexedDB 업그레이드가 필요하다
**When** LocalStorage 5MB 제한에 도달한다
**Then** IndexedDB로 자동 마이그레이션이 시작된다
**And** "더 많은 저장 공간을 사용하기 위해 데이터베이스를 업그레이드하고 있습니다" 토스트가 표시된다
**And** 마이그레이션 완료 후 스냅샷 제한이 10개에서 100개로 확장된다
**And** IndexedDB 데이터베이스명: `bm_builder_canvas_v2`
**And** idb 라이브러리로 IndexedDB 연동이 구현된다
**And** 마이그레이션된 데이터는 영구 보존된다 (브라우저 종료 후에도 유지)
**And** 사용자가 "업그레이드 완료" 알림을 받는다

### Epic 6 Stories

#### Story 6.1: 3개 노드 완료 시 부분 내보내기 버튼 표시

**사용자:** 캔버스 사용자
**원하는 기능:** 3개 이상 노드 완료 시 부분 내보내기 버튼 표시
**가치:** 진행 중인 작업을 초안으로 내보내어 피드백을 받을 수 있다

**Acceptance Criteria:**

**Given** 사용자가 캔버스에서 작업 중이다
**When** 완료된 노드 수가 3개 미만이다
**Then** "부분 내보내기" 버튼이 표시되지 않는다
**And** 헤더에 "완료 X/7"만 표시된다 (X < 3)
**And** "3개 이상 노드 완성 시 부분 내보내기가 가능합니다" 안내가 툴팁으로 표시된다

**Given** 완료된 노드 수가 3개가 된다
**When** 3번째 노드가 완료된다
**Then** "부분 내보내기" 버튼이 헤der 우측에 표시된다
**And** 버튼 색상은 파란색(#3b82f6)이다
